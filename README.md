# DepGuard Backend

This repository contains the backend services for the DepGuard dependency risk analysis platform.

## Project structure
```
backend/
  app/
    __init__.py
    main.py                 # FastAPI entry point (health check)
    config.py               # Pydantic‑settings based configuration
    services/
      lockfile_parser.py    # Parses npm ``package-lock.json`` (v2/v3) ``packages`` format
      graph_engine.py       # Builds a NetworkX directed graph from the parsed data
      __init__.py
    api/
      __init__.py
tests/
  fixtures/
    lockfile_v2.json       # minimal v2 example
    lockfile_v3.json       # minimal v3 example
  test_graph_engine.py
requirements.txt
README.md
```

## Getting started
1. **Create a virtual environment** (recommended)
   ```bash
   python -m venv .venv
   source .venv/bin/activate   # on Windows: .venv\Scripts\activate
   ```
2. **Install dependencies**
   ```bash
   pip install -r requirements.txt
   ```
3. **Run the FastAPI app** (optional, health check only)
   ```bash
   uvicorn backend/app/main:app --reload
   ```
   Open <http://127.0.0.1:8000/health> to see `{"status": "ok"}`.

## Running the tests
The test suite validates the lockfile parser and graph engine against a set of fixtures covering direct, transitive, development, optional, duplicate, and unresolved dependencies.
```bash
pytest -q
```
All tests should pass.

## Configuration
Environment variables are loaded via **pydantic‑settings** (see `backend/app/config.py`).
```dotenv
MONGODB_URI=<your‑mongodb‑uri>
GITHUB_APP_ID=<your‑github‑app‑id>
GITHUB_PRIVATE_KEY_PATH=<path‑to‑private‑key>
```
No secrets are committed to the repository.

## Known limitations
* The parser currently ignores version ranges when resolving a dependency – it links a parent to *any* installed package with the matching name under its `node_modules` tree. This matches npm's deterministic install layout but does not handle workspace‑style hoisting.
* Cycles are detected by NetworkX; the graph builder will still create edges that form cycles, but path enumeration is limited by a `limit` parameter to avoid exponential blow‑up.
* Only the ``packages`` section of npm lockfiles v2/v3 is supported; older lockfiles that use the legacy ``dependencies`` map are not parsed.
* No OSV or risk scoring logic is included yet (planned for later phases).
